# Mewse（喵织梦）V1 产品需求文档

- **文档版本**：v1.0
- **适用阶段**：V1 阶段（核心工作台：本地存储与作品管理 + 写作编辑器）
- **产品名称**：Mewse（喵织梦）

---

## 1. 产品概述

### 1.1 产品定位
Mewse（喵织梦）是一款面向个人中长篇及短篇创作者的**本地优先（Local-First）桌面端写作软件**。产品秉持“克制而专注”的理念，实现**“视觉排版、底层存储与发布格式”三层分离**：
- **写作时**：提供接近实体阅读体验的舒适排版与低干扰写作界面；
- **存储时**：以人类直观可读的本地文件夹与纯净文本（`.txt`）文件落盘，天然兼容第三方云盘同步与外部纯文本工具接力编辑；
- **发布时**：一键输出适配各类连载或内容平台的标准纯文本格式。

### 1.2 目标用户与核心场景
- **目标用户**：有长篇连载或中短篇创作需求的个人创作者（网文作者、小说创作者、独立文字作者）。
- **核心场景**：
  1. 在本地离线环境下进行日常高效码字、章节管理与稿件安全留存；
  2. 随时记录零散灵感与大纲草稿，并对照大纲或前文撰写新章节；
  3. 通过个人云盘（如 iCloud Drive、OneDrive、坚果云等）跨设备同步作品目录，并使用第三方纯文本工具（如 WPS、系统记事本等）接力编辑；
  4. 章节完稿后一键转换为符合平台排版习惯的纯文本进行发布投递。

### 1.3 版本范围界定（Scope）
| 范围类别 | 涵盖内容 |
| :--- | :--- |
| **V1 核心范围（In Scope）** | 书库与书架管理、已有纯文本作品导入、作品层级目录管理、本地纯净存储与同步冲突保护、防丢稿与历史快照、核心写作编辑器、阅读级排版与视图模式、精准字数统计与每日码字日历、一键复制发布与单章文件导出。 |
| **非 V1 范围（Out of Scope）** | 世界书档案及行内批注/伏笔联动（规划于 V2）、AI 写作辅助与审稿（规划于 V3）、移动端/平板端原生适配（规划于 V4）、整书合并及多格式电子书导出（后续规划）、非纯文本格式导入（如 `.docx`/`.pdf`）及单文件自动拆章、自建云同步服务及账号体系、多人协同编辑、富文本行内样式与复杂排版（加粗、斜体、删除线、多级标题、表格、代码块、多媒体混排等）。 |

## 2. 功能需求清单

> **优先级说明**：
> - **P0（核心必备）**：构成“存储 + 写作”最小完整闭环的基础能力，V1 必须完整交付；
> - **P1（重要增强）**：显著提升长篇创作效率、安全性与使用体验的重点能力，V1 计划内交付。

### 2.1 书库与作品管理

| 编号 | 需求名称 | 优先级 | 需求描述与业务规则 |
| :--- | :--- | :---: | :--- |
| **FR-1.1** | 书库（Workspace）选择与切换 | P0 | 1. 首次启动应用时，引导用户选择一个本地文件夹作为总书库根目录（支持选择位于第三方云盘同步目录内的路径）。<br>2. 支持用户在后续使用中随时切换或重新指定书库根目录，并记忆最近使用的书库及上次打开的作品位置。 |
| **FR-1.2** | 书架首页展示 | P0 | 1. 以网格卡片形式展示当前书库内的全部作品。<br>2. 每张作品卡片需清晰展示：作品名称、封面（纯色块或自定义封面图）、全书累计字数、最近编辑时间、连载状态标签。<br>3. 点击任意作品卡片即可进入该作品的写作工作台。 |
| **FR-1.3** | 新建与导入作品 | P0 | 1. **新建作品**：支持输入作品名称、选择封面样式/颜色、设定初始连载状态，创建后自动初始化标准作品目录结构。<br>2. **导入已有作品（纯 `.txt` 适配）**：<br>   - **规范作品导入**：支持将本地符合本软件目录规范的既有作品文件夹直接识别并导入当前书库书架；<br>   - **外部纯文本与批量导入**：支持导入单个或批量多个含 `.txt` 稿件的作品目录，以及在新建或已有作品指定卷下批量选择多个 `.txt` 章节文件导入（默认仅适配纯 `.txt` 文本，不解析 `.docx`/`.pdf` 等格式，亦不进行整本单文件自动拆章）；<br>   - **标题首数字智能排序（可选）**：批量导入章节时，提供可勾选项“自动识别文件名首个阿拉伯数字排序”——开启后仅提取文件名中出现的第一段连续阿拉伯数字作为排序依据，不识别中文数字（例如 `第17章-遇见一只小黑猫.txt` 识别为 `17`，而非后面的“一”），未含阿拉伯数字的文件按名称顺序顺延排在末尾；关闭则按常规文件名序导入，导入前支持列表预览确认并自动生成规范序号前缀；<br>   - **导入净化与编码兼容**：自动识别 `UTF-8`/`GBK`/`GB18030` 等常见编码并统一转为 `UTF-8`（无 BOM）副本落盘，自动剥离段首冗余全角空格（`　　`）及多余首尾空白并规范换行，全程只读复制，不改动用户原始文件。 |
| **FR-1.4** | 作品信息编辑与移除 | P1 | 1. 支持修改作品名称（同步反映至作品本地文件夹名称）、更换封面样式、切换连载状态（如：`连载中`、`已完结`、`暂停`）。<br>2. 支持移除或删除作品，操作前必须明确告知是否影响本地磁盘文件并提供安全确认，防止误删全书稿件。 |

### 2.2 作品目录与结构管理

| 编号 | 需求名称 | 优先级 | 需求描述与业务规则 |
| :--- | :--- | :---: | :--- |
| **FR-2.1** | 固定三段式作品目录结构 | P0 | 单个作品内部采用固定清晰的目录结构，降低长篇组织的心智负担：<br>1. **顶部「灵感与草稿箱」**：固定置顶，用于存放未归入正文的灵感碎片、设定草稿、分章大纲等独立文档；<br>2. **中部「卷 → 章」两级正文树**：严格限定为“卷（Volume）”与“章（Chapter）”两级层级，不支持无限嵌套子目录；<br>3. **底部「回收站」**：固定置底，存放被软删除的卷、章及草稿文档。 |
| **FR-2.2** | 卷、章与草稿的增删改 | P0 | 1. 支持在草稿箱内新建草稿文档，在作品内新建卷，在指定卷下新建章节。<br>2. 支持对卷、章节、草稿进行重命名，新名称实时同步到底层本地文件夹或文件名称。<br>3. 目录树支持展开与折叠各卷章节列表。 |
| **FR-2.3** | 目录拖拽排序与跨卷移动 | P0 | 1. 支持通过拖拽调整：卷的排列顺序、同卷内章节顺序、跨卷移动章节、以及草稿箱内文档顺序。<br>2. 支持通过拖拽或快捷操作将草稿箱中的成熟文档移入指定卷转正为正式章节，也支持将卷内章节移回草稿箱。<br>3. 排序或归属变更后，底层文件夹或文件的顺序标识与目录归属需同步更新，确保在系统文件管理器中浏览时结构一致。 |
| **FR-2.4** | 软删除与作品级回收站 | P0 | 1. 删除草稿、章节或整卷时，默认执行软删除并移入当前作品的「回收站」，记录删除时间与原所属位置信息，严禁未经确认直接物理删除用户文稿。<br>2. 支持在回收站内预览已删除项目，支持单个或批量一键恢复至原位置（若原所属卷已被删除，则提示恢复至默认位置或连同原卷一并恢复）。<br>3. **手动清理**：支持在回收站内进行**单选或复选批量彻底删除**，以及**一键清空回收站**；所有彻底删除操作前必须经过不可逆二次确认。<br>4. **自动清理周期**：移入回收站的项目自删除之日起保留 **180 天**，超期后系统自动执行彻底清理；回收站列表需直观展示各项目距离自动清理的剩余保留天数。 |

### 2.3 本地存储、外部同步与数据安全

| 编号 | 需求名称 | 优先级 | 需求描述与业务规则 |
| :--- | :--- | :---: | :--- |
| **FR-3.1** | 人类可读的本地目录映射 | P0 | 1. 书库、作品、草稿箱、卷与章节直接映射为本地磁盘上的标准文件夹与 `.txt` 文件。<br>2. 目录及文件命名需包含人类直观可读的顺序标识与名称，无需打开本软件即可在系统文件管理器中快速定位和浏览全部文稿。 |
| **FR-3.2** | 纯净文本（`.txt`）正文存储规范 | P0 | 1. 所有章节与草稿内容均以标准纯文本（`.txt`）格式保存，统一采用 `UTF-8`（无 BOM）编码落盘；读取外部导入或修改后的文件时需自动兼容 `UTF-8` 与 `GBK`/`GB18030` 等常见中文编码，防止跨平台乱码。<br>2. 保持极简自然换行语义：敲击一次回车即对应纯文本自然分段换行，外部文本工具打开即可直观阅读，无需人为插入冗余空行。<br>3. 正文文件中**不得写入**软件私有元数据头或隐藏配置段落，且正文首行**不强制包含**章节标题文本，确保用户在移动端或第三方文本工具（如 WPS）中打开时看到 100% 纯净的正文。<br>4. 作品元数据（作品基础信息、章节排序索引、历史快照、回收站等）需与常规正文目录相隔离，避免干扰第三方工具阅读与检索。 |
| **FR-3.3** | 无感自动保存与状态提示 | P0 | 1. 用户输入停顿短暂时间后自动触发保存；在切换当前编辑文档、窗口失焦或关闭应用前，立即触发保存。<br>2. 界面需持续提供极简、清晰的保存状态反馈（如：`已保存`、`保存中`、`保存异常`）。 |
| **FR-3.4** | 异常防损坏持久化保障 | P0 | 所有文件写入操作必须具备防截断与防损坏保障：即使发生意外断电、程序异常退出或云盘同步文件占用，也不得导致原有文稿被写空或内容部分损坏。 |
| **FR-3.5** | 外部文件变更感知与同步 | P1 | 软件需能够感知当前打开作品目录的外部文件系统变动（如云盘同步更新或外部编辑器修改）：<br>1. **外部新增/重命名**：检测到目录内新增或重命名的合规 `.txt` 文件时，自动纳入作品目录管理并在目录树展示。<br>2. **外部修改（无本地冲突）**：若当前打开文档在本地无未保存变更，自动刷新编辑器内容，并通过轻量提示告知用户“已同步外部更改”。<br>3. **外部修改（存在本地冲突）**：若本地存在未保存修改且外部文件同时发生变化，必须拦截静默覆盖，弹出版本冲突对比界面，供用户选择处理方式：**保留本地版本**、**采用外部版本**、或**将冲突内容另存一份至草稿箱**。 |
| **FR-3.6** | 章节历史快照与回退 | P1 | 1. **手动快照**：支持用户随时为当前章节手动创建一个历史版本快照，并可附带简短备注（如“大改结局前”）。<br>2. **自动快照**：当满足特定保护条件（如切换章节且本章节正文净变动超过一定阈值，例如 300 字）时，自动按日留存滚动历史快照。<br>3. **查看、对比与恢复**：支持浏览指定章节的历史快照列表、将任意快照与当前正文进行左右文本差异对比、并支持一键回退至所选快照版本（执行回退前自动为当前正文留存保护快照）。 |

### 2.4 核心写作编辑器

| 编号 | 需求名称 | 优先级 | 需求描述与业务规则 |
| :--- | :--- | :---: | :--- |
| **FR-4.1** | 独立章节标题栏 | P0 | 1. 编辑区顶部设置独立于正文编辑器的章节标题输入框，标题修改自动同步至目录树及本地文件名。<br>2. 在标题框内按回车（`Enter`）键，光标自动聚焦至正文首段，保证连贯的起笔体验。<br>3. 章节标题不混入正文内容流，且不计入正文字数。 |
| **FR-4.2** | 极简纯文本编辑与可扩展视觉层 | P0 | 编辑器聚焦纯文本文学创作，彻底摒弃富文本样式干扰，并通过“数据与视觉分离”架构预留可扩展前端视觉渲染能力：<br>1. **基础文档结构**：仅保留普通段落与场景分割线（独占一行的 `---`，在编辑器内渲染为视觉分隔线）。<br>2. **零富文本样式**：不引入加粗、斜体、删除线、多级标题、表格、代码块、自定义字色等持久化富文本格式，杜绝 `*`、`~`、`#` 等符号对中文标点及正文内容的误触发。<br>3. **可扩展前端视觉装饰层**：编辑器需具备非侵入式的纯前端视觉渲染扩展通道（如 V1 的对话文本高亮，以及为后续版本世界书词条提示、AI 审稿波浪线等预留渲染机制），所有视觉效果均只在画布层面动态呈现，**绝不写入或污染**底层 `.txt` 文件。 |
| **FR-4.3** | 零常驻工具栏与极简交互 | P0 | 1. 默认写作状态下界面不展示固定格式工具栏，保持低干扰沉浸画布。<br>2. 禁用会篡改纯文本语义的 Markdown 行内快捷语法转换，仅保留常规纯文本编辑快捷键。<br>3. 预留选区气泡菜单（Bubble Menu）扩展槽位，供后续版本（如 V2 行内批注与世界书收录、V3 AI 局部诊断）挂载动作；V1 阶段保持界面克制，不弹冗余格式菜单（或仅按需提供「复制」「全书检索选中词」等极轻操作）。 |
| **FR-4.4** | 纯文本粘贴净化 | P0 | 从外部来源（网页、办公文档、富文本笔记等）复制内容并粘贴至编辑器时，默认自动剥离所有富文本样式（字体、字号、颜色、背景、HTML 标签等），仅保留纯文本内容与基础段落换行结构；并自动清理段落开头的冗余全角空格（`　　`）及多余缩进空白（避免与视觉首行缩进叠加），保持与底层纯净存储规范一致。 |
| **FR-4.5** | 对话文本视觉高亮（可开关） | P1 | 1. 支持自动识别中文对话引号（`“……”` 及 `「……」`）包裹的文本，在编辑器内以柔和微弱的色彩与叙述文本进行视觉区分，辅助作者把控对话节奏与密度。<br>2. **单段闭合隔离规则**：匹配逻辑严格限定在单个自然段内部完成（支持同段内嵌套单引号 `‘……’`/`『……』`），严禁跨段落匹配；当某段落存在未闭合的前引号时，不得向后穿透染色后续段落。<br>3. 提供明确开关可随时启用或关闭该效果。<br>4. 该高亮基于前端视觉装饰层实现，严格属于纯视觉辅助，**绝不写入或改变**底层 `.txt` 文件内容。 |
| **FR-4.6** | 单章查找与替换 | P0 | 1. 支持通过快捷键（如 `Ctrl/Cmd + F`、`Ctrl/Cmd + H`）在当前编辑文档内唤起轻量查找与替换浮层。<br>2. **查找能力**：支持关键词高亮标记、匹配总数与当前命中序号展示、上/下一个结果快速跳转，并支持“区分大小写”选项。<br>3. **替换能力**：支持“替换当前”与“全部替换”，且批量替换操作支持通过常规撤销（`Undo`）一步回退。<br>4. 替换范围聚焦于正文可见文本内容，不得误破坏场景分割线结构。 |
| **FR-4.7** | 全书关键词检索 | P1 | 1. 支持在当前作品范围内按关键词检索所有正式章节与草稿箱文档（不含回收站）。<br>2. 列表展示匹配文档名称及命中上下文摘要片段，点击任意结果可直接打开对应文档并定位高亮至命中位置。 |

### 2.5 阅读级排版、多视图与专注模式

| 编号 | 需求名称 | 优先级 | 需求描述与业务规则 |
| :--- | :--- | :---: | :--- |
| **FR-5.1** | 全局排版设置 | P0 | 支持用户在设置面板中实时调节并持久化保存阅读级排版参数（所有排版仅作用于视觉呈现，不污染底层文件内容）：<br>1. 正文字体（支持预设常用文学字体及调用系统已安装字体）；<br>2. 正文字号（支持如 14px–24px 范围调节）；<br>3. 行高（支持如 1.6–2.2 范围调节）；<br>4. 段落间距；<br>5. 正文版心最大宽度。 |
| **FR-5.2** | 段首自动视觉缩进 | P0 | 1. 提供“段首自动缩进两字符”开关（默认推荐开启）。<br>2. 开启后，编辑器在视觉上呈现标准中文出版物首行缩进两格效果；作者分段只需敲击一次回车，无需手动输入全角空格，底层存储保持纯净段落结构。 |
| **FR-5.3** | 护眼主题配色 | P0 | 内置至少 4 套护眼阅读主题，覆盖工作台与编辑画布，支持一键切换：<br>1. 纯白简约模式；<br>2. 羊皮纸护眼暖色模式；<br>3. 清新淡绿护眼模式；<br>4. 深色暗夜模式。 |
| **FR-5.4** | 左右双栏分屏对照视图 | P1 | 1. 支持点击分屏按钮在主编辑区开启或关闭左右双栏视图，并支持拖拽分隔线自由调整左右两栏宽度比例。<br>2. 左右两栏各自具备独立的文档选择器与滚动条，支持在同一部作品内任意两份文档之间（如“左栏大纲/上一章 + 右栏当前新章”）并排对照阅读或同步编辑。<br>3. **同文档双栏规则**：允许左右两栏同时打开同一篇文档；此时两栏共享同一份实时编辑状态并保留各自独立的滚动位置与光标位置——任一侧的内容或标题修改均实时同步至另一侧并统一触发自动保存，杜绝彼此覆盖冲突，满足长章节“前文对照、后文续写”需求。 |
| **FR-5.5** | 专注模式（Zen Mode） | P1 | 1. 支持通过界面按钮或快捷键一键进入或退出专注模式，自动隐藏左侧目录树与顶部非必要栏位，最大化沉浸写作画布。<br>2. 支持可选的“打字机居中滚动”开关：开启后输入过程中当前光标所在行始终保持在屏幕纵向舒适焦点区域（约中部黄金位置）。 |

### 2.6 字数统计与平台交付

| 编号 | 需求名称 | 优先级 | 需求描述与业务规则 |
| :--- | :--- | :---: | :--- |
| **FR-6.1** | 精准字数统计与明细卡片 | P0 | 1. **统计口径**：默认展示的「本章有效字数」严格统计**汉字 + 中英文标点符号 + 英文单词/数字字符**；严格剔除所有空格、换行符、章节标题及独立场景分割线符号。<br>2. **常驻与明细**：底部状态栏常驻显示当前章节有效字数；鼠标悬停或点击字数区域时，弹出明细面板展示：`汉字 + 标点数`、`纯汉字数（不含标点）`、`本章今日净增字数`、`全书总字数`，并提供查看码字统计日历的快捷入口。 |
| **FR-6.2** | 一键复制为平台发布格式 | P0 | 1. 编辑区右上角提供常驻【复制本章】按钮及旁侧格式预设配置入口。<br>2. 点击复制后，按用户预设规则将当前章节转换为标准发布纯文本并写入系统剪贴板，同时弹出确认提示（例如：“已按发布格式复制，共 X,XXX 字”）。<br>3. **发布预设可配置项**：<br>   - 段首是否自动补齐两个全角空格（`　　`）；<br>   - 段落之间是否额外保留一行空行；<br>   - 场景分割线输出样式选择（`———`、`***` 或空行）；<br>   - 首行是否自动附带章节标题。 |
| **FR-6.3** | 单章文件导出 | P1 | 1. 支持将单个章节（或草稿文档）导出为独立 `.txt` 文件并由用户选择本地保存路径（整书合并导出不在 V1 范围内）。<br>2. **支持导出模式**：<br>   - **平台发布格式（`.txt`）**：沿用平台发布预设规则，按预设格式化排版输出；<br>   - **纯净原稿格式（`.txt`）**：保留原始段落换行结构，可选是否首行附带章节标题。<br>3. 导出操作只生成副本文件，不得影响或改动书库内的原始文件。 |
| **FR-6.4** | 每日码字统计日历（热力图） | P1 | 1. **热力图展示**：提供类似 GitHub 贡献图的按日码字热力图日历（支持从书架首页与工作台字数面板打开），以颜色深浅直观反映创作者每日码字产出强度。<br>2. **统计规则**：以本地自然日（`00:00–24:00`）为单位记录并持久化每日有效字数净增量；批量导入外部已有作品或章节的初始字数**不计入**当日码字新增量，避免扭曲全年热力图色阶；若因大幅删稿导致单日净增为负，当日展示值以 `0` 计。<br>3. **维度与交互**：支持查看当前书库汇总或切换查看单部作品的热力图；鼠标悬停或点击任意日期方格，显示对应日期与当日码字字数，并辅助展示连续创作天数、当月/当年累计码字等轻量统计指标。 |

## 3. 非功能性需求

| 维度 | 编号 | 需求描述 |
| :--- | :---: | :--- |
| **性能与流畅度** | **NFR-1** | 1. 面对百万字级别（数百章节）的中长篇作品，书架加载与目录树渲染应保持流畅，无明显卡顿。<br>2. 单章万字以上长文编辑时，连续高速输入、对话视觉高亮与字数统计不得造成打字掉帧或输入延迟。<br>3. 自动保存与快照生成应在后台平稳执行，不阻塞用户的键盘输入与界面交互。 |
| **可靠性与数据安全** | **NFR-2** | 1. 遵循本地优先与用户数据完全自主原则：软件不强制联网、不上传作品正文至任何远程服务器。<br>2. 文件持久化与重命名操作需具备故障容错能力，确保异常退出场景下已有稿件零损坏。<br>3. 任何可能造成不可逆内容覆盖或删除的操作（如版本冲突覆盖、回收站单选/批量彻底删除、清空回收站、删除作品）均需提供清晰的决策确认；回收站自动清理需具备明确 180 天期限及剩余天数提示。 |
| **易用性与交互规范** | **NFR-3** | 1. 界面保持视觉克制与低噪点，核心创作路径直观，无需复杂学习成本即可上手使用。<br>2. 提供完整常用桌面端快捷键支持（如保存、撤销/重做、查找与替换、全书检索、专注模式开关、分屏开关等），并适配 Windows 与 macOS 的系统按键习惯。 |
| **平台与兼容性** | **NFR-4** | 1. V1 面向主流桌面操作系统（Windows、macOS）提供独立桌面端应用体验，适应不同分辨率及窗口缩放尺寸。<br>2. V1 建立的本地目录结构与正文存储规范需保持向后兼容，确保未来版本迭代升级时已有作品可无缝平滑迁移。 |

## 4. 后续版本演进方向（非 V1 范围）

以下能力明确排除在 V1 开发与验收范围之外，仅作为产品中长期演进方向供参考：

- **V2 — 世界书档案系统（Worldbook）与行内批注**：支持人物、势力/地点、物品/规则、时间线等设定档案管理，引入作者行内批注/伏笔备忘能力，并在正文中实现设定词条与伏笔批注的联动展示及角色动态状态追踪。
- **V3 — 克制型 AI 写作副驾驶**：在不直接代写正文的前提下，支持用户自带模型密钥进行剧情逻辑与设定一致性体检、卡文灵感发散、局部表达诊断及新设定自动提取归档。
- **V4 — 移动与平板端适配**：将本地写作与跨端同步体验延伸至手机及平板触屏设备。
- **后续增强能力**：整书合并导出及多格式出版排版导出（如整本 `.txt`/`.md`/`.epub` 等）。
