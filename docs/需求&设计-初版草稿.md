# 私人创作编辑器 - 一阶段 MVP 需求与架构规范 (v1.0)

## 1. 项目定位与核心设计哲学
本项目是一款面向个人长/中短篇创作者的**本地优先（Local-First）独立桌面写作软件**。
* **克制而专注**：摒弃花哨的富文本排版，践行**“视觉渲染与存储内容彻底分离”**——写的时候享受阅读级排版，存的时候是人类可读的干净 Markdown，发的时候一键输出各平台标准纯文本。
* **云盘与跨端友好**：底层直接采用直观的本地文件夹与 `.md` 文件映射，天然支持挂载在 iCloud Drive / OneDrive / 坚果云目录下，允许用户在手机/平板端用任意第三方 Markdown 软件随时接力编辑。
* **渐进式可扩展架构**：一阶段聚焦**【作品存储管理 + 核心编辑器】**，但在目录结构、状态管理、Tiptap 插件机制与 UI 布局上，必须严格按规范为二阶段（世界书档案）、三阶段（AI 辅助副驾驶）及未来 Tauri 移动端打包预留扩展槽位。

---

## 2. 技术栈选型（严格约束）
* **跨平台应用框架**：`Tauri v2`（Rust 后端负责本地文件 I/O、原子写入、文件变更监听；未来可直接复用编译 iOS/iPadOS/Android 端）
* **前端框架**：`React 18+` + `TypeScript` + `Vite`
* **状态管理**：`Zustand`（按领域拆分为独立 Store：`useWorkspaceStore`, `useBookStore`, `useEditorStore`, `useSettingsStore`）
* **UI 与样式**：`Tailwind CSS` + `shadcn/ui`（无障碍基础组件）+ `CSS Variables`（驱动阅读排版与主题切换）
* **核心编辑器内核**：`Tiptap v2`（基于 ProseMirror 的 Headless 框架，严禁引入重型富文本默认工具栏）
* **图标库**：`Lucide React`

## 3. 本地存储与文件目录规范（核心基石）

### 3.1 人类可读的目录树结构
用户首次启动需选择一个本地文件夹作为总书库（`Workspace`，可位于云同步盘内）。每部作品对应一个子文件夹，结构如下：

```text
MyWritingWorkspace/
 ├── workspace.json                # 全局书库配置与最近打开记录
 └── 诡秘之海/                      # 单部作品根目录（文件夹名即书名）
      ├── _meta/                   # 元数据隐藏目录（避免干扰移动端阅读）
      │    ├── book.json           # 作品信息、目录树UUID映射、章节状态
      │    └── snapshots/          # 章节历史快照存放处 (按 chapId 分目录)
      ├── _trash/                  # 作品级回收站（软删除的章节/卷移至此，永不物理直删）
      ├── _worldbook/              # 【二阶段预留】世界书设定档案目录（一阶段自动创建空目录）
      ├── 00_灵感与草稿箱/          # 固定顶置目录：存放未归入正文的灵感与碎片 .md
      ├── 01_第一卷_迷雾初现/        # 卷目录（序号前缀 + 卷名）
      │    ├── 001_雨夜来客.md      # 章节正文文件（三位序号前缀 + 章节标题）
      │    └── 002_古旧怀表.md
      └── 02_第二卷_暗流涌动/
```

### 3.2 存储格式与外部修改兼容（File Watcher）
1. **纯净 `.md` 正文规范**：
   * 章节 `.md` 文件内**不写 YAML Frontmatter**（所有章节状态、创建时间、UUID 均维护在 `_meta/book.json` 中），确保手机端打开时 100% 纯净无代码干扰。
   * 文件第一行不强制包含 `# 章节名`（章节名直接对应文件名去除序号前缀的部分，并在编辑器独立标题栏展示）。
2. **重命名与拖拽排序机制**：
   * 用户在目录树拖拽调整章节/卷顺序，或修改章节标题时，后端自动重算序号前缀并执行安全的文件重命名，同步更新 `book.json`。
3. **云盘同步与文件监听（防覆盖机制）**：
   * 使用 Rust (`notify` crate) 或 Tauri fs watch 监听当前打开作品的目录。
   * **场景 A（外部新增/改名）**：用户在手机端往卷文件夹里新建了一个 `.md`，桌面端检测到后自动将其纳管注册进 `book.json` 并在目录树显示。
   * **场景 B（外部修改正文）**：若当前打开章节的磁盘文件 `mtime`/Hash 发生变化：
     * 若本地编辑器无未保存修改 -> 自动静默热更新编辑器内容，顶部轻提示“已同步外部更改”。
     * 若本地编辑器存在未保存冲突 -> 拦截自动覆盖，弹出【版本冲突对比弹窗】（保留本地 / 采用外部文件 / 另存一份到草稿箱）。
4. **原子保存机制**：所有文件落盘必须采用“先写临时文件 `.tmp` 再 Rename 替换目标文件”的原子操作，杜绝断电或云盘占用导致的空文件损坏。

## 4. 一阶段（MVP）功能模块详述

### 模块一：书架与作品管理
1. **书架首页**：
   * 网格卡片展示书库内所有作品：书名、纯色块/自定义封面、全书总字数、最近编辑时间、连载状态标签。
   * 支持：新建作品、导入已有作品文件夹、切换书库根目录（Workspace）。
2. **单书左侧目录树（固定层级）**：
   * 结构固定为：顶置 `💡 灵感与草稿箱` + 中部 `📂 卷 (Volume) -> 📄 章 (Chapter)` 两级列表 + 底部 `🗑️ 回收站`。
   * 支持新建卷/章、重命名、拖拽排序、软删除至回收站、从回收站恢复。
   * 章节状态小圆点/标签切换：`草稿 (灰)` / `修改中 (黄)` / `已定稿 (绿)`。
3. **防丢稿双保险**：
   * **无感自动保存**：输入停顿 `1000ms` 或切换章节/失焦时自动保存，状态栏显示极简保存状态（已保存 / 保存中）。
   * **历史快照（Snapshots）**：支持一键手动创建当前章节快照（可附简短备注，如“大改结局前”），并在切换章节且字数变动超过 300 字时自动留存每日滚动快照；支持查看历史快照列表、左右对比及一键回退。

### 模块二：核心写作编辑器（基于 Tiptap 深度定制）
1. **严格裁剪的文档格式（Schema）**：
   * **顶部独立标题框**：与 Tiptap 正文实例分离的 `<input>`，回车自动聚焦正文首段；标题不计入正文字数。
   * **仅保留的块与内联格式**：普通段落 (`Paragraph`)、加粗 (`Bold`)、斜体 (`Italic`)、删除线 (`Strike`)、场景分割线 (`HorizontalRule`，输入 `---` 触发)。
   * **零固定工具栏**：平时界面无任何格式按钮；仅在鼠标选中文本时弹出极简 **Bubble Menu（气泡菜单）**。
   * **纯文本粘贴净化**：默认从外部粘贴内容时自动剥离富文本 HTML 样式（颜色、字号、网页背景），仅保留基础段落与换行。
2. **创作者专属语法与装饰器**：
   * **作者行内批注（Inline Note）**：
     * 交互：气泡菜单点击“添加批注”或输入快捷指令（如 `【【` 自动补全），在正文中渲染为柔和醒目的胶囊/高亮块（如 `[批注：这里核对一下唐代官制]`）。
     * 存储：序列化到 `.md` 文件时存为标准 HTML 注释语法 `<!-- @note: 这里核对一下唐代官制 -->`（手机端纯文本可读，常规渲染自动隐藏，导出正文时 100% 自动剔除，且不计入正文字数）。
   * **对话微弱高亮（纯视觉 Decoration，可开关）**：
     * 基于 ProseMirror `Decoration.inline` 实时正则匹配中文双引号 `“……”` 及 `「……」` 内的文本，赋予微弱的专属字色区分，**绝不写入底层 `.md` 文件**。

### 模块三：多视图、阅读级排版与一键交付
1. **全局排版引擎（CSS 变量驱动，内容零污染）**：
   * 设置面板支持实时调节：正文字体（内置/调用系统思源宋体、霞鹜文楷、系统黑体等）、字号（14px~24px）、行高（1.6~2.2）、段落间距、纸张最大宽度。
   * **段首自动缩进开关**：开启后通过 CSS `text-indent: 2em` 实现视觉首行缩进两格——用户打字换行只需敲一次 `Enter`，无需手动敲全角空格。
   * **护眼主题**：内置至少 4 套配色（纯白简约、羊皮纸护眼暖色、清新淡绿、深色暗夜模式）。
2. **左右双栏分屏视图（Split View）**：
   * 点击右上角“分屏”按钮，主编辑区拆分为左右独立双栏，各自拥有独立的章节选择器与滚动条。支持左右拉拽，加宽或缩小某一屏。
   * 典型场景：左栏打开“上一章”或“灵感草稿箱里的大纲”，右栏专注撰写新章节；支持同一作品内任意两个文档并排编辑或只读对照。
3. **专注模式（Zen Mode）**：
   * 快捷键（如 `F11` 或 `Cmd/Ctrl + \`）一键收起左侧目录树与顶部栏，支持可选的“打字机居中滚动（光标始终保持在屏幕纵向黄金位置）”。
4. **精准字数统计口径**：
   * 底部状态栏常驻显示核心指标：**本章字数 = 汉字 + 标点符号 + 英文单词/数字字符（严格剔除所有空格、换行符、标题、Markdown 语法符及 `<!-- @note -->` 批注内容）**。
   * 鼠标悬停/点击状态栏字数，弹出小卡片展示明细：`汉字+标点数`、`纯汉字数（不含标点）`、`本章今日新增字数`、`全书总字数`。
5. **一键复制为平台发布格式（Export to Clipboard）**：
   * 右上角常驻 **【复制本章】** 按钮（旁附格式预设小齿轮）：
     * 自动剥离全部 Markdown 标记符（`**`, `*`, `~~`）及所有作者行内批注；
     * 按用户勾选的发布预设格式化：
       * `[x] 段首自动补齐两个全角空格 (　　)`
       * `[ ] 段落之间额外保留一行空行`
       * `分割线替换为：[ ——— / *** / 空行 ]`
       * `[ ] 首行附带章节标题`
     * 点击后直接写入系统剪贴板并弹出 Toast 提示：“已按发布格式复制（共 X,XXX 字）”。

## 5. 架构预留规范（Agent 编码时必须遵守的接口契约）

为确保二阶段、三阶段无缝接入，一阶段代码结构必须预留以下扩展点：

### 5.1 UI 布局预留：三栏弹性工作台（Workbench Layout）
主工作台采用标准三栏弹性容器：
* `LeftSidebar`：作品目录树（一阶段实现，可折叠）。
* `CenterStage`：单栏 / 左右双栏编辑器容器（一阶段实现）。
* `RightInspector`：**【预留右侧抽屉容器】**。一阶段仅在右上角预留槽位接口（或用于临时放置“历史快照列表”），后续二阶段直接挂载“世界书卡片速查”，三阶段挂载“AI 审稿/灵感对话面板”，无需改动主编辑器与分屏布局。

### 5.2 Tiptap 编辑器插件插槽（Extension Slots）
封装编辑器实例时，将自定义插件模块化放在 `src/editor/extensions/` 下，并预留两个核心机制：
1. **实体扫描装饰器通道（Entity Decoration Pipeline）**：
   * 将一阶段的“对话引号高亮”写成一个通用的 ProseMirror Plugin 范式。二阶段只需传入世界书的关键词词典（角色名/别名/地点），即可直接复用同一套 `DecorationSet` 机制实现“正文中角色名自动虚线高亮 + 鼠标悬停弹出人设浮窗”，零侵入正文数据。
2. **选区上下文提取接口（Editor Context Bridge）**：
   * 在 `useEditorStore` 中暴露标准方法：`getCurrentContext()`（返回当前章节纯文本、当前光标所在段落、当前鼠标选中文本及前后各 N 段上下文），供三阶段 AI 辅助模块直接读取，避免 AI 模块直接耦合 Tiptap 实例。

### 5.3 数据层与跨端抽象层（Platform Service Layer）
* **禁止在 React UI 组件内直接调用 `@tauri-apps/plugin-fs` API**！
* 必须封装统一的存储服务层 `src/services/storageService.ts`（定义 `loadBook`, `saveChapter`, `watchWorkspace` 等接口）。这样未来适配移动端特殊沙盒路径或扩展云备份插件时，只需修改 `storageService` 一处。
* 新建作品时默认初始化空的 `_worldbook/index.json`，提前锁定目录契约。

## 6. 后续阶段演进蓝图（供全局架构参考，一阶段暂不开发）

* **Phase 2：世界书档案系统（Worldbook）**
  * `_worldbook/` 下存储分类设定（角色、势力/地点、物品/规则、时间线）。
  * 正文联动：实体词自动微弱下划线，悬浮预览人设卡片；支持记录角色随章节推进的“动态状态变更”（防吃书）。
* **Phase 3：克制型 AI 写作副驾驶（AI Copilot，不代写正文）**
  * 支持自带 API Key（OpenAI 兼容接口 / Claude / DeepSeek）。
  * 核心能力：① 结合世界书进行“防吃书与逻辑一致性体检”；② 卡文多走向破局头脑风暴；③ 局部神态/词汇反向词典与病句节奏诊断；④ 章节写完后自动扫描提取新出场人物/道具归档至世界书。
* **Phase 4：平板与手机端适配（Tauri Mobile）**
  * 基于现有核心代码增加响应式触屏单栏布局与软键盘工具条，编译 iPadOS / iOS / Android 客户端。

## 7. 分步实施计划（Milestones）

* **Milestone 1：Tauri v2 脚手架与本地文件系统底座**
  * 搭建 `Tauri v2 + React + TS + Tailwind + Zustand` 基础工程。
  * 实现 `storageService`：工作区选择、书架读写、人类可读的卷/章 `.md` 创建、重命名、原子写入与软删除回收站。
* **Milestone 2：单书工作台与目录树交互**
  * 完成书架首页 UI 与单书三栏骨架布局。
  * 实现左侧目录树（草稿箱 + 卷/章列表 + 拖拽重排自动更新文件序号 + 章节状态标签）。
* **Milestone 3：Tiptap 核心编辑器与阅读级排版**
  * 集成 Tiptap + Markdown 双向转换，实现独立标题框、气泡菜单、分割线、`<!-- @note: ... -->` 行内批注节点及对话引号高亮 Decoration。
  * 实现全局排版设置（字体、字号、行距、段首自动两格缩进、3 套护眼主题）与“汉字+标点”精准字数统计栏。
* **Milestone 4：双栏分屏、外部监听、历史快照与一键发布复制**
  * 实现左右双栏分屏对照视图与全屏专注模式。
  * 接入 Rust 文件监听（外部云盘同步热更新与冲突弹窗）、章节历史快照回退，以及右上角【一键复制为平台纯文本格式】功能。
```
