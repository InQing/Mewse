- **文档版本**：v1.1（新增本地书库与云备份目录双向同步、云端整库导入及冲突快照机制）

- **设计依据**：
  - 《Mewse（喵织梦）V1 产品需求文档》（v1.1）
  - 《Mewse（喵织梦）V1 UI 设计初稿》（v1.1）与 V1 交互原型
- **文档定位**：本文档用于定义 V1 版本各核心模块的业务流程、状态流转、底层数据语义联动及异常边界处理规则，作为后续技术架构设计、本地存储 Schema 定义、编码实现与测试验收的直接依据。

## 1. 设计总览与核心约束

### 1.1 V1 核心业务闭环

V1 围绕“本地优先（Local-First）、云端备份互备”原则构建从进入软件到输出发布稿的完整闭环：

```text
应用启动与书库挂载
    ├── 首次启动 / 路径失效 ──▶ 选择本地主书库（可选关联云备份目录） 或 从云端目录导入整库到本地
    └── 已有有效书库 ────────▶ 打开检测云端更新 ──▶ 进入书架首页（可选一键继续上次作品）
                                                          │
          ┌───────────────────────┬───────────────────────┼───────────────────────┐
          ▼                       ▼                       ▼                       ▼
     新建作品               导入已有作品             打开作品工作台          云备份增量同步
                                                          │               (后台防抖推送 / 冲突仲裁)
                    ┌─────────────────────────────────────┼─────────────────────────────────────┐
                    ▼                                     ▼                                     ▼
            三段式目录管理                        纯文本写作与安全落盘                  辅助阅读与平台交付
   (草稿箱 / 卷→章 / 180天回收站)          (独立标题 / 视觉层 / 原子保存 / 冲突仲裁)    (双栏 / 专注 / 检索 / 快照 / 统计 / 导出)
```

### 1.2 三层分离设计原则

功能流程的设计与实现必须严格遵守“视觉排版、底层存储、发布格式”三层分离：

1. **视觉渲染层**：段落缩进、护眼主题、对话高亮、查找命中高亮、打字机居中、场景分割线可视化均只作用于前端渲染画布，**不得写入或修改**底层正文的 `.txt` 内容。
2. **底层存储层**：草稿与章节以纯净的 `UTF-8（无 BOM）` `.txt` 文件落盘，不写入软件私有元数据头（如 YAML Frontmatter）或隐藏标记；作品配置、目录树顺序索引、历史快照、回收站、每日码字流水全部隔离存放在独立元数据区内。
3. **发布输出层**：一键复制与单章平台格式导出仅在内存中按当前“全局发布预设”对纯净原稿进行格式化拼装并输出副本，**不得改动**书库内的原始文件。

### 1.3 V1 功能边界锁定

以下能力明确不在 V1 功能设计范围内（界面与逻辑均不保留不可用的占位逻辑）：
- 世界书档案管理及正文行内词条/批注联动（V2，但同步机制已通过目录白名单预留 `_worldbook/` 扩展能力）；
- AI 写作辅助、诊断与提取（V3）；
- 移动端及平板触屏适配（V4）；
- 自建云同步服务器、用户账号体系及对接各家私有云在线 SDK/API；
- 整书合并及多格式（`.epub` / `.docx` / `.pdf`）导入或导出；
- 富文本行内样式（加粗、斜体、删除线、多级标题、表格、代码块、多媒体）及单 `.txt` 整本自动拆章。

## 2. 全局生命周期与书库管理流程

### 2.1 应用启动与书库挂载流程（FR-1.1）

```text
[应用启动]
    │
    ▼
读取本地应用配置 (lastWorkspacePath, syncTargetPath, lastOpenedBookId, lastOpenedDocId)
    │
    ├── 不存在 lastWorkspacePath ───────────────────────────────▶ [首次启动引导页]
    │                                                                 ├── 方式 A：选择/新建本地主书库（可引导关联云备份目录）
    │                                                                 └── 方式 B：从云端备份目录导入整库到本地目标目录
    └── 存在 lastWorkspacePath                                        │
            │                                                         ▼
            ▼                                                校验目录可读/可写权限
      校验目录是否存在且可读写                                        │
            ├── 否 ──▶ [书库失效引导提示]（定位新路径 / 新建书库） ◀──┤ 失败（提示原因）
            │                                                         │ 成功
            └── 是 ───────────────────────────────────────────────────┴──▶ 挂载本地书库 & 初始化配置
                                                                                  │
                                                                                  ▼
                                                                       若已关联云备份目录：执行书库级增量对比
                                                                       (仅云端更新→提示确认拉取；双端冲突→进冲突处理)
                                                                                  │
                                                                                  ▼
                                                                       扫描书架作品列表 & 统计数据
                                                                                  │
                                                                                  ▼
                                                                         进入【书架首页】
```

**核心业务规则**：
1. **本地主书库与云目录分离**：用户日常创作始终以纯本地目录作为主书库（高速读写、不受网盘锁文件干扰），并可随时将主书库关联至一个第三方云盘映射目录（如 iCloud Drive、OneDrive、坚果云同步文件夹等）作为云端备份与多设备同步桥梁；若本地主书库本身已位于云盘目录中，亦可正常工作并由外部变更感知流程兜底。
2. **记忆与恢复**：应用持久化记录最近使用的本地书库路径、关联的云备份目录路径，以及每部作品最近一次打开的文档 ID 与编辑/阅读位置。从书架点击某部作品卡片进入工作台时，先执行该作品与云端的快速一致检查（若已关联云目录），随后定位至上次最后编辑的文档（若该文档已移入回收站或被移除，则自动回退至该作品首个可用章节或草稿；若全书无文档，则展示空工作台引导创建）。
3. **自动巡检前置**：书库挂载及进入作品时，自动触发一次回收站过期（超过 180 天）清理校验。

### 2.2 切换书库流程（FR-1.1）

当用户在书架页或工作台触发「切换书库」并选定新目录后，按以下顺序执行安全切换：

1. **编辑态与同步收口**（若当前处于某部作品工作台内）：
   - 检查是否存在未解决的云端/外部版本冲突。若存在，阻断直接切库并提示先完成冲突处理；
   - 若当前打开文档（单栏或双栏任一侧）存在未保存修改（`Dirty`），立即执行同步原子保存落盘；若保存失败，中止切换并提示异常详情；
   - 若已关联云备份目录且后台存在待同步变更队列（`PendingSet`），尝试执行一次快速增量备份推送（若云目录暂时不可用，保留本地变更状态供下次挂载该书库时继续同步）。
2. **资源释放**：注销当前书库/作品的文件系统监听器（File Watcher）及后台同步定时器，清空内存中作品目录树与文档正文缓存。
3. **新书库校验与挂载**：校验新目标目录读写权限 → 失败则提示错误信息并尝试回滚保持原书库；成功则更新 `lastWorkspacePath` → 加载对应云备份关联配置并执行更新检测 → 扫描新书库作品并跳转至【书架首页】。

### 2.3 书架展示、作品新建与信息维护流程（FR-1.2, FR-1.4）

1. **书架加载流程**：
   - 遍历书库根目录下的合规子目录（排除隐藏目录及书库元数据文件），读取各作品元数据与连载状态。
   - 若某作品缺失部分元数据索引但包含合规正文结构，自动在后台补建基础索引而不丢失用户文稿。
   - 卡片聚合展示：作品名称、封面（纯色/内置封面样式或自定义图片）、全书累计有效字数、最近编辑时间、连载状态标签（`连载中`、`已完结`、`暂停`）。
   - 无作品时展示空白引导状态，突出「新建作品」与「导入作品」入口。

2. **新建作品流程**：
   - 用户输入作品名称、选择封面样式/颜色、设定初始连载状态（默认 `连载中`）。
   - **重名与合法性校验**：过滤本地文件系统非法字符（`\ / : * ? " < > |` 等）并校验当前书库下是否已存在同名作品目录；若存在则提示修改名称。
   - **目录初始化**：在书库根目录下创建作品文件夹及标准子目录：
     - 作品元数据目录（隔离存放作品信息、排序索引、快照、码字统计）；
     - 作品级回收站目录；
     - 顶部「灵感与草稿箱」目录；
     - 默认初始卷目录（如 `01_第一卷`）及初始空白章节（如 `001_第一章.txt`），随后刷新书架列表（或按交互设计直接进入/留在书架）。

3. **作品信息编辑与移除/删除流程**：
   - **修改作品信息**：支持修改作品名、更换封面、切换连载状态。修改作品名时需校验目标目录是否被占用或重名，先执行本地作品文件夹重命名，成功后再更新作品元数据与书架卡片；若被系统文件管理器或云盘占用导致改名失败，回滚界面展示并提示具体原因。
   - **从书架移除 vs 彻底删除**：
     - **移除**：仅从书架跟踪索引移除（或对书库外引用解除关联，若为本地书库内文件夹可提供明确区分选项），**绝不删除**磁盘文稿并明确在确认框中告知。
     - **删除作品**：属于高危不可逆操作，必须弹出强制二次确认框，明确标示作品名称、总字数及“该操作将永久删除本地磁盘上的全部作品文件夹与稿件”，经用户明确确认后执行。

### 2.4 导入已有作品、批量章节与云端整库导入流程（FR-1.3, FR-1.1）

V1 支持三类导入场景（规范作品、外部纯文本、云备份整库），均严格遵守**“全程只读复制外部源、绝不修改原始文件、仅适配 `.txt` 纯文本、不计入每日码字热力图增量”**四项铁律。

#### 场景 A：导入规范 Mewse 作品文件夹
1. 用户选择本地文件夹 → 校验内部是否存在合规的作品元数据标识与目录规范。
2. 若该作品文件夹与当前书库内已有作品同名，提示冲突处理（自动追加后缀重命名导入或由用户重新命名）。
3. 执行只读递归复制至当前书库目录 → 校验内部索引与实际 `.txt` 文件一致性（补充缺失记录或剔除失效索引）→ 完成导入并更新书架。

#### 场景 B：导入外部散落 `.txt` 作品目录 / 在指定卷下批量导入 `.txt` 章节
1. **来源选择与格式过滤**：
   - 用户选择一个外部文件夹（作为整部作品导入，子文件夹可按需映射为单级卷或扁平导入）或在目标作品/指定卷下多选 `.txt` 文件；
   - 自动忽略非 `.txt` 文件（如 `.docx`、`.pdf`、图片等），并在预览阶段汇总提示“已跳过 N 个非 `.txt` 文件”，不执行整本单文件自动拆章。
2. **标题与序号识别规则（可开关）**：
   - 导入预览界面提供复选框：**“自动识别文件名首个阿拉伯数字排序”**（默认推荐开启）。
   - **开启时**：
     - 对每个 `.txt` 文件名（去除 `.txt` 后缀）提取**第一段连续 ASCII 阿拉伯数字** `[0-9]+` 作为排序键值（例如 `第17章-遇见一只小黑猫.txt` 提取键值 `17`，忽略后文的中文数字“一”）。
     - 含数字的文件按数值升序排列（数值相同时按原文件名自然序次级排序）；不含任何阿拉伯数字的文件统一排在末尾，内部按文件名自然序顺延。
   - **关闭时**：全部文件按系统常规文件名自然序排列。
   - **标题清理**：按配置生成规范的三位顺序前缀（如 `001_`、`002_`），预览列表实时展示：`原文件名` → `目标序号 + 章节标题` → `探测编码`，允许用户在确认前查看顺序。
3. **编码兼容与文本净化流水线**：
   - 对每个待导入文件只读读取字节流，按优先级嗅探编码：`UTF-8 (含 BOM / 无 BOM)` → `GB18030`（兼容 `GBK` / `GB2312`）；
   - 将换行符统一标准化为 `\n`（兼容 `\r\n` 与 `\r`）；
   - **段落净化**：按段落拆分后，自动剥离段首冗余全角空格（`　`）及前导常规空白，清除文档首尾多余空行，保留段内有效标点与独立场景分割线 `---`；
   - 统一以 `UTF-8（无 BOM）` 写入当前书库的目标目录。
4. **统计基准初始化**：
   - 将导入生成的各章节有效字数直接设为该章节的 `countedBaseline`（已统计基准字数），**不写入**当日及历史任何一天的“每日码字新增量”，仅汇总入作品当前全书总字数。

#### 场景 C：从云端备份目录导入整座书库到本地（FR-1.1 跨设备接力）
1. **适用场景**：用户在另一台设备上安装 Mewse 并首次启动（或切换书库），需要直接拉取云端备份的完整书库到本地工作。
2. **目标选择与校验**：
   - 用户选定源「云备份目录」（例如 `OneDrive/MewseSync`）与本机「本地书库存放目录」；
   - 校验云目录内合规作品结构及本机目标目录可写性（若本地目标目录非空且存在同名作品，提示用户处理冲突或改选空目录）。
3. **全量拉取与基线建立**：
   - 将云备份目录下的全部作品（含草稿、卷章 `.txt`、`_meta/book.json`、`_meta/daily_stats.json`、`_trash/`、历史快照等；V2 同步包含 `_worldbook/`）只读复制至本地目标目录；
   - 写盘成功后，在本地自动生成初始同步基线账本 `sync_baseline.json`（记录所有已拉取文件的内容 Hash），并将新本地书库自动关联至该云备份目录；
   - 直接进入【书架首页】，立即可无缝继续之前设备的全部创作进度与码字热力图统计。

## 3. 作品目录与本地磁盘映射流程

### 3.1 固定三段式结构与本地映射规则（FR-2.1, FR-3.1, FR-3.2）

单部作品在本地磁盘上固定映射为“顶部草稿箱 + 中部两级卷章树 + 底部隔离回收站”，目录及文件均带有直观序号前缀以便在系统文件管理器中直接浏览：

```text
<书库根目录>/<作品名称>/
 ├── _meta/                       # 元数据隔离区（不展示于目录树，不干扰第三方文本工具）
 │    ├── book.json               # 作品信息、目录树结构与 UUID 映射、字数统计基准
 │    ├── snapshots/              # 按 docId 分目录存放的历史快照（含云端/本地冲突备份）
 │    └── daily_stats.json        # 该作品按自然日记录的净增字数流水
 ├── _trash/                      # 作品级软删除回收站物理存储与删除记录索引
 ├── 00_灵感与草稿箱/              # 固定置顶区：存放未归入正文的灵感、大纲、设定草稿 .txt
 │    ├── 001_第二卷分章大纲.txt
 │    └── 002_关于沈舟的过去.txt
 ├── 01_第一卷·归港/               # 卷目录（两位或以上序号前缀 + 卷名）
 │    ├── 001_雨夜来客.txt         # 正文章节（三位序号前缀 + 章节标题）
 │    └── 002_旧灯塔.txt
 └── 02_第二卷·远海/
      └── 001_离港之前.txt
```

**书库根目录与设备私有区**（同步范围之外，永不参与云端备份）：

```text
<本地书库根目录>/
 ├── .mewse/                       # 设备私有区：仅本机有效，不同步
 │    ├── workspace.json           # 最近书库、关联云目录路径、上次打开作品/文档/滚动位置
 │    ├── sync_baseline.json       # 双向同步基线账本：相对路径 → { contentHash, syncedAt }
 │    └── sync_queue.json          # 待推送队列与冲突挂起记录（损坏后可安全重建）
 ├── <作品 A>/                     # 作品目录（结构见上）
 └── <作品 B>/
```

> **注**：为保持目录清晰和向后兼容，V1 仅支持“草稿箱（单级）”、“卷 → 章（严格两级）”结构，不支持卷内再嵌套子文件夹。正文章节序号采用“卷内从 `001` 独立连续编号”或“全书递增”须保持单一确定规则；为使每卷在系统文件管理器中自洽且跨卷拖拽时无需重命名其他未受影响卷的章节文件，**推荐采用卷内独立 `001` 起编**（界面展示可同步呈现卷内顺序或全书章节位次）。

### 3.2 纯净 `.txt` 正文规范（FR-3.2, FR-4.2）

1. **编码与换行**：所有草稿及正文章节一律采用 `UTF-8（无 BOM）` 保存，换行符统一为 `\n`。
2. **零元信息污染**：文件内部绝不写入标题头、YAML Frontmatter、时间戳、状态标签或任何格式标记；正文首行即第一段内容。
3. **极简结构映射**：
   - 编辑器内单个普通段落 ↔ 文件内单行文本（一次回车即产生一个自然分段，无需额外空行）；
   - 编辑器内场景分割线 ↔ 文件内独占一行的 `---`。

### 3.3 卷、章与草稿的增删改及拖拽重排流程（FR-2.2, FR-2.3）

1. **新建操作**：
   - **新建草稿 / 章节 / 卷**：计算目标容器当前最大序号 `+ 1`，生成唯一 `docId` / `volumeId` 与带序号前缀的物理文件/文件夹。新建章节或草稿后，自动在工作台选中并聚焦其标题栏（新建后空文件立即落盘，避免仅存在于内存中）。
2. **重命名与文件名映射**：
   - 无论是在左侧目录树重命名还是在编辑器顶部独立标题栏修改章节/草稿标题，均触发标题联动更新流程：
   - **非法字符处理**：显示标题允许保留常用符号（如 `：`、`？`、`·`），映射为物理文件名时自动替换或剔除操作系统非法字符（`\ / : * ? " < > |`），并在 `book.json` 中保存原始显示标题与物理文件名的映射关系。
   - **磁盘重命名时序**：更新本地文件名前开启短期「内部写入锁（Echo Suppression）」，执行物理重命名成功后更新 `book.json`；若重命名因文件被外部锁住而失败，恢复原名称并弹窗/状态提示报错。
3. **拖拽排序与跨区移动**：
   - **合法移动矩阵**：
     - 卷 ↔ 卷（同级顺序调整）；
     - 章 ↔ 同卷其他位置（卷内排序）；
     - 章 ↔ 另一卷（跨卷移动）；
     - 草稿 ↔ 草稿（草稿箱内排序）；
     - 草稿 → 指定卷（**转正为正式章节**）；
     - 卷内章节 → 草稿箱（**移回草稿箱**，保留正文与历史快照）。
     - **禁止操作**：卷不可拖入其他卷或草稿箱内；回收站不参与直接拖拽。
   - **序号重算与防碰撞机制**：
     1. 若正在拖拽移动的是当前打开文档且处于 `Dirty` 状态，先执行落盘保存；
     2. 挂起/标记对应目录的 File Watcher 自触发忽略窗口；
     3. 计算变更集合的新旧路径映射表；
     4. 采用**“两段式临时中转重命名”（或按序错位重命名）**执行物理文件移动与序号重写（例如 `001` 与 `002` 互换时先将 `001` 移至临时名，再将 `002` 改为 `001`，最后把临时名改为 `002`），彻底杜绝重命名过程中因同名文件暂存引发的覆盖或冲突；
     5. 同步更新 `book.json` 目录树顺序与文档归属信息，并在界面即时更新（若当前文档所属卷变更，顶部位置面包屑同步刷新）。

### 3.4 软删除与作品级回收站闭环流程（FR-2.4）

```text
[用户删除 草稿 / 章 / 整卷]
         │
         ▼
是否包含当前编辑器（单/双栏）正在打开的文档？
    ├── 是 ──▶ 先暂停该文档保存队列；若存在未保存修改则先安全落盘 → 将当前编辑焦点安全切换至相邻有效文档（无则进入空画布态）
    └── 否 ──▶ 继续
         │
         ▼
开启内部写入锁，将对应文件（或整卷文件夹）物理移入 _trash/<trashId>/
记录回收站元数据：{ trashId, type, title, originalParentId, originalParentTitle, deletedAt, expireAt(+180天), wordCount }
         │
         ▼
从正文目录树与 book.json 活动列表移除，更新全书字数缓存（不计入当日码字负净增）
```

**回收站后续操作流程**：

1. **预览**：点击回收站列表中的项目（草稿、章节或卷内章节），可在抽屉或预览视图中只读查看其正文内容、原所属位置、删除日期与**距离自动清理剩余天数**（计算方式：`Math.max(0, Math.ceil((expireAt - now) / 1天))`）。
2. **恢复流程**：
   - **恢复草稿**：直接移回 `00_灵感与草稿箱/` 末尾，分配新序号，恢复活动状态；
   - **恢复整卷**：按卷原名（重名则自动加后缀）恢复至正文卷列表末尾，连同其下所有章节及关联快照恢复可见；
   - **恢复单章**：
     - 检查 `originalParentId` 对应的卷是否仍处于活动目录树中；
     - **原卷存在**：一步恢复至原卷末尾并分配新序号；
     - **原卷已被软删除（仍在回收站中）或已被彻底删除**：弹出轻量选择确认——允许用户选择**“恢复至其他现有卷 / 草稿箱”**或（当原卷在回收站时）**“连同原卷一并恢复”**。
   - **字数统计隔离**：恢复操作仅还原文件归属与作品总字数，恢复的原有字数直接设置回文档 `countedBaseline`，**不计入**当日码字净增量。
3. **手动彻底删除与一键清空**：
   - 支持单选、复选批量勾选彻底删除，以及一键清空全部回收站；
   - 执行前必须弹出**不可逆二次确认对话框**，明确列出待删除项目数/名称，声明“彻底删除后将从本地磁盘永久清除，不可恢复”，确认后物理销毁 `_trash/<trashId>/` 及其关联的 `_meta/snapshots/` 下对应快照数据。
4. **180 天超期自动清理**：
   - 触发时机：书库挂载时、打开对应作品时、以及软件驻留运行期间每日跨越自然日零点时；
   - 遍历回收站索引，筛选 `now >= expireAt` 的过期条目，自动执行物理文件及关联快照的永久清理并移除回收站记录（清理前不额外弹窗打断用户写作，但回收站界面自始至终清晰展示剩余保留天数）。

## 4. 核心写作编辑器与数据安全流程

### 4.1 独立标题栏与正文编辑流（FR-4.1 ~ FR-4.4）

1. **打开文档流程**：
   - 若编辑器当前已有打开的文档且处于 `Dirty` 状态，**先同步执行保存落盘**；若前文档处于“冲突未解决”或“保存异常”状态，阻断无感切换并提示用户先处理当前异常（避免用户误以为已切走且保存成功）。
   - 读取目标 `.txt` 文件并探测编码（兼容外部修改存入的 `GBK`/`GB18030`），按 `\n` 拆分为段落集合与 `---` 分割线节点。
   - 更新编辑器内容、初始化单文档撤销/重做栈、记录当前文档字数基准、从状态记忆中恢复上次退出该文档时的滚动条/光标位置（新文档聚焦正文首段）。
   - 独立标题栏加载当前文档显示名称；标题变更按防抖与失焦触发重命名映射流程，**不计入正文字数、不写入 `.txt` 首行**；在标题输入框按 `Enter` 键时，将光标移动并聚焦至正文首段起始位置。

2. **纯文本编辑与粘贴净化**：
   - 屏蔽加粗、斜体、删除线、列表、代码块等富文本行为及 Markdown 行内转换快捷语法；
   - 输入 `---` 独占一行并换行时，在编辑器视图层渲染为场景分隔线组件，序列化落盘时仍保持纯文本 `---` 行；
   - **粘贴净化**：监听粘贴事件，仅提取纯文本流（`text/plain`），过滤所有 HTML 标签及内联样式；按段落拆行，自动剥离每段段首的冗余全角空格（`　`）及前导普通空格（防止与“段首自动视觉缩进”叠成四格缩进），并合并成单次可撤销的编辑器事务。
   - **选区气泡菜单预留**：编辑器架构中内置选区变化监听器与轻浮层坐标槽位（Bubble Menu Slot）；V1 阶段保持界面克制，默认不弹出冗余格式工具条，仅按需预留纯轻量化动作扩展钩子。

### 4.2 可扩展视觉装饰层与对话高亮流程（FR-4.2, FR-4.5）

1. **纯前端装饰器通道（Decoration Pipeline）**：
   - 编辑器维护独立于底层文本模型的装饰层注册表，按层叠加样式（例如：`Layer 1: 对话文本视觉高亮`、`Layer 2: 查找与定位高亮`；后续版本挂载 `V2: 世界书词条`、`V3: AI 审稿提示`）。
   - 所有装饰层仅在文本变更或开关状态变化时对受影响段落进行增量计算并挂载虚拟行内标记，**序列化保存、字数统计与导出复制时完全忽略装饰层节点**。

2. **对话文本视觉高亮规则（严格单段闭合隔离）**：
   - 当排版面板中的「对话文本高亮」开关为开启状态时生效，关闭时立即清空全部对话高亮装饰：
   - **逐段独立扫描**：严格以单个自然段为执行边界，段末强制重置匹配状态机，**绝对禁止跨段传递高亮状态**。
   - **成对闭合匹配**：
     - 识别中文双引号 `“……”` 与直角引号 `「……」` 作为外层对话定界符；
     - 允许对话内部合法嵌套单引号 `‘……’` 与双直角内引号 `『……』`，不打断外层对话区间；
     - **未闭合隔离规则**：若某段落存在未闭合的前引号（例如仅有 `“` 而本段结束前未出现配对的 `”`），该未闭合前引号不触发跨段染色，且本段之后的所有后续段落均保持正常叙述文本样式（为防止输入未闭合前引号时整段闪烁，仅在扫描到成对闭合引号时才为该闭合区间渲染对话高亮，或严格截断于当前段尾且绝对不渗透至下一段）。

### 4.3 无感自动保存与防损坏持久化状态机（FR-3.3, FR-3.4）

每个当前打开并处于编辑中的文档维护如下保存状态机：

```text
           [加载完成 / 写入成功]
                 Clean (已保存)
                   │        ▲
      用户输入 /   │        │ 原子写入成功 &
      标题修改     ▼        │ 无新 Dirty 产生
                 Dirty (待保存)
                   │
      触发条件满足 │ (停顿防抖 800-1000ms / 切章 / 失焦 / 窗口关闭 / 分屏切换)
                   ▼
                 Saving (保存中…)
                   │
          ┌────────┴────────┐
          ▼                 ▼
     写入成功           写入异常 (权限不足 / 磁盘满 / 外部文件锁占用)
          │                 │
          ▼                 ▼
    更新基准指纹        Error (保存异常) ──▶ 状态栏高亮报错 + 阻止静默丢弃 + 提供重试/另存
```

**原子写入协议（防截断与防损坏）**：
1. **串行写入队列**：同一文档同一时刻只允许一个落盘事务执行；若正在 `Saving` 期间用户又产生新输入，置位 `pendingSave = true`，待当前落盘完成后立即调度下一轮保存，确保内存与磁盘最终一致。
2. **原子替换步骤**：
   - 先将正文序列化为完整 `UTF-8（无 BOM）` 字节流写入同级临时文件（如 `.<filename>.mewse.tmp`），调用系统文件同步刷新（`fsync`）确保落入磁盘介质；
   - 申请该文件路径的**内部写入锁（Echo Suppression）**，执行原子 `rename` 覆盖目标 `.txt` 文件；
   - 记录写盘完成后的文件 `mtime` 与内容 SHA-256 哈希指纹，随后延迟窗口（如 `500ms–1000ms`）释放写入锁。
3. **退出前强制刷盘**：拦截窗口关闭事件（`CloseRequested`），遍历所有处于 `Dirty` 或 `Saving` 状态的文档完成最终落盘（同步写完或确认触发自动快照），确认无异常后再允许进程退出；若落盘失败，弹窗阻断退出并提示用户处理。

### 4.4 本地与云端双向备份同步流程（FR-3.5）

本模块是 V1 数据安全的第二道防线：本地始终是写作主库，云目录（第三方云盘映射文件夹）承担**存储备份**与**多设备同步**两项职责。由于云盘客户端已在系统层完成上云/落盘，软件对“云端”的所有操作在实现上等价于**两个本地目录之间的文件比对与搬迁**，因此无需绑定任何云厂商 SDK，天然兼容 OneDrive、iCloud Drive、坚果云、NAS 挂载盘等任意具备本地同步目录的存储。

#### 4.4.1 同步引擎抽象：一个薄适配层，消灭未来的迁移成本

同步引擎仅依赖 5 个文件原语：`列出清单`、`读取内容`、`原子写入`、`删除`、`探测目录可写`。V1 只实现一个适配器 **`CloudFolderTarget`（云目录目标）**，未来若需接入 WebDAV / S3 / 云 API（如 V4 移动端受沙盒限制无法放置同步目录时），只需新增 `WebDavTarget` / `S3Target`，**上层的三向比对、冲突仲裁、快照保护逻辑保持不变**。

#### 4.4.2 同步范围与过滤白名单

| 分类 | 内容 | 是否同步 |
| :--- | :--- | :---: |
| 正文与草稿 | 草稿箱及全部卷目录下的 `.txt` | ✅ V1 |
| 作品结构元数据 | `_meta/book.json`、`_meta/daily_stats.json` | ✅ V1（`book.json` 走结构合并，见 4.4.5） |
| 回收站与快照 | `_trash/`、`_meta/snapshots/` | ✅ V1 |
| 世界书（预留） | `_worldbook/` | ⏳ V2 开白名单即纳入 |
| 设备私有配置 | `.mewse/workspace.json`、`sync_baseline.json`、`sync_queue.json`、字体/窗口偏好 | ❌ 永不同步 |
| 临时文件 | `*.tmp`、`*.mewse.tmp` | ❌ 永不同步 |

> 设计要点：同步引擎按**目录白名单规则**运作而非写死“只传 `.txt`”，因此 V2 引入世界书时只需放开一条规则，无需重构同步链路。

#### 4.4.3 同步时机：本地快路径 + 云端异步慢路径（性能保障）

1. **本地落盘（快路径，毫秒级）**：打字停顿防抖、切章、失焦、退出时先原子写入本地硬盘，**绝不等待任何云端 I/O**；写入成功后仅将变动文件的相对路径推入内存 `PendingSet`。
2. **云端推送（慢路径，异步批量）**：复用同一套保存/目录变更事件链，但采用更宽松的合并窗口（连续停顿约 `3–5s`、切换章节、窗口失焦、退出应用、手动触发「立即同步」），且**只增量推送 `PendingSet` 内的文件**，绝不全库扫描。万字体量书库每次同步也只处理被改动的那一两份文件。
3. **云端检查（低频按需）**：仅在打开书库、打开作品、窗口重新获得焦点、用户手动检查时触发。先用 `文件大小 + mtime` 做廉价预筛，仅对疑似变化的文件计算内容哈希，避免频繁全库哈希拖慢性能。

#### 4.4.4 三向对比状态机（核心判定逻辑）

严禁仅凭 `mtime` 判断新旧（网盘回拉文件常刷新时间戳，且多设备时钟存在偏差）。基线账本 `sync_baseline.json` 记录每份文件**上次两端一致时的内容哈希 `Base`**，每次比对执行三向比较（`Local` vs `Base` vs `Cloud`）：

```text
                    [触发同步检查：打开书库/作品、窗口聚焦、定时、手动]
                                      │
                                      ▼
                    逐一比对文件：Local / Base / Cloud 三方哈希
                                      │
   ┌──────────────┬──────────────┬────┴─────┬──────────────┬──────────────────┐
   ▼              ▼              ▼          ▼              ▼                  ▼
两边一致      仅本地改动      仅云端改动    双方都改      一端新增        一端缺失
(L==C==B)    (L≠B, C==B)   (L==B, C≠B)  (L≠B,C≠B,L≠C)                 (对方删除 or 我方未上传)
   │              │              │          │              │                  │
 静默通过     推送至云目录    提示或自动拉取  弹冲突仲裁     按新增处理        按缺失确认处理
             并更新 Base     （见 4.4.6）  （见 4.4.6）   并建立基线         （见 4.4.7）
```

- **两边一致**：静默通过，云朵显示绿色（已同步）。
- **仅本地改动**：异步增量推送至云目录，推送成功后更新 `Base`；若云目录不可写，保留 `PendingSet` 稍后重试，云朵显示暖橙色并说明原因。
- **仅云端改动**：V1 按用户确认制处理（见 4.4.6），不做静默覆盖。
- **双方都改**：真冲突，进入弹窗仲裁（见 4.4.6）。
- **一端新增**：纳管/推送并建立基线，属常规操作，不打扰用户。
- **一端缺失**：绝不静默删除或补传，先确认后处置（见 4.4.7）。

#### 4.4.5 `book.json` 等结构元数据的合并策略

正文 `.txt` 可按文件级二选一，但 `book.json` 承载整部作品的目录树，若双端离线各自新增章节后直接覆盖，将丢失对方新增的目录记录。因此：

1. **以物理文件为准做自愈校准**：合并后扫描磁盘上的实际 `.txt` 文件（文件名已含 `001_` 等序号前缀，顺序可重建），补齐缺失的目录条目、剔除已失效条目。
2. **按 `docId` 做集合并集**：同时存在于两端的文档保留双方属性，标题冲突时取较新的修改时间。
3. **仅当同一文档的正文本身分叉时**，才升级为文件级冲突并弹窗仲裁——结构层合并对用户完全透明，不出现在交互中。

#### 4.4.6 打开时的更新提示与冲突仲裁（用户可感知的唯一入口）

**场景 1：仅云端更新（本地自上次同步后未改动）**

打开书库或作品检测到云端存在更新时，展示轻量更新提示（列出待更新的作品/章节及数量），用户确认后从云端拉取并覆盖本地对应文件；覆盖前自动为被替换的本地旧版**留存保护快照**，操作完成后以 Toast 告知「已从云端更新 N 个文件」。

**场景 2：双端分叉冲突（本地与云端各自改过同一文档）**

拦截静默覆盖，弹出模态对比界面（左右并排高亮差异），由用户显式决策：

| 用户选择 | 系统动作 |
| :--- | :--- |
| **保留本地版本** | 本地内容原子覆盖云目录对应文件 → 更新 `Base` → **自动将云端版本存为该文档一条历史快照**（备注 `云端冲突备份 · YYYY-MM-DD HH:mm`） |
| **采用云端版本** | 云端内容覆盖本地文件（编辑器若正打开则热刷新）→ 更新 `Base` → **自动将本地版本存为该文档一条历史快照**（备注 `本地冲突备份 · YYYY-MM-DD HH:mm`） |
| **另存冲突副本** | 冲突一方另存为草稿箱新文档（`原章节名_冲突副本_时间.txt`），主文档采用用户指定的版本，确保双份留存 |

> 无论选择哪一侧，**另一侧版本必定进入历史快照时间线**，可随时在「历史快照」抽屉中 Diff 对比并回退，实现“选一版、快照另一版”的零丢失承诺。

#### 4.4.7 删除与缺失文件的保护规则

同步链路中最危险的是“一端没了就把另一端也删掉”。因此：

1. **云端缺文件、本地存在**：可能是网盘同步延迟或异常；先提示用户确认，选择「重新备份到云端」或「按云端删除移入本地回收站」，**默认永不静默删除本地正文**。
2. **本地缺文件、云端存在**：可能是本地误删或换了新设备；提示「从云端恢复」或「确认删除云端副本」，默认倾向恢复。
3. **正常删除链路**：用户在软件内删除章节 → 软删除进 `_trash/` → 该删除动作作为一次合法变更同步至云端（含 `_trash/` 内容），使另一设备也能看到相同回收站状态，语义一致且可恢复。

#### 4.4.8 同步状态与异常反馈（联动 5.4 状态栏与云备份面板）

| 状态 | 云朵呈现 | 悬停提示 |
| :--- | :--- | :--- |
| 已关联且已同步 | 绿色圆点 | 已连接到云端，本地修改将自动备份 |
| 正在同步 | 绿色圆点 + 轻量脉冲 | 正在同步 N 个文件… |
| 存在待推送变更（云目录暂不可写） | 暖橙色圆点 | 本地修改尚未备份，云目录当前不可写入 |
| 未关联云备份目录 | 暖橙色圆点 | 尚未关联云备份目录，点击设置 |
| 存在未处理冲突 | 暖橙色圆点 + 提示点 | 检测到 N 处版本冲突，点击处理 |
| 同步失败 | 暖橙色圆点（避免刺眼红） | 同步异常：<具体原因>，可手动重试 |

### 4.5 外部文件变更感知与版本冲突处理流程（FR-3.5）

> **职责边界**：4.4 处理“本地主书库 ↔ 云备份目录”之间的主动双向同步；本节处理“本地主书库自身被外部改写”的被动感知（第三方编辑器直接改文件、本地书库正好位于云盘目录时由网盘客户端回写、用户手工在文件管理器里增删改）。两者最终都汇聚到同一套版本冲突弹窗与快照留存机制，区别只在于变更来源判定。

File Watcher 持续监听当前已打开作品目录（排除 `_meta/`、`*.tmp` 内部临时文件），对文件系统事件进行短期防抖聚合并进入以下分支判定：

```text
[File Watcher 捕获磁盘文件变更事件]
         │
         ▼
是否在内部写入锁窗口内且内容哈希与软件最后一次写入一致？
    ├── 是 ──▶ 判定为软件自身行为（Echo），忽略该事件
    └── 否 ──▶ 确认为外部修改（云盘同步 / 第三方编辑器修改）
                   │
                   ├── [事件类型：新增合规 .txt]
                   │       └─▶ 探测编码读取（兼容 UTF-8 / GBK / GB18030）→ 若在卷或草稿箱内则纳管进 book.json 与目录树，初始化字数基准，刷新 UI
                   │
                   ├── [事件类型：外部重命名 / 移动]
                   │       └─▶ 更新 book.json 映射与目录树展示；若当前打开此文档，同步更新顶部面包屑与标题关联
                   │
                   ├── [事件类型：外部删除]
                   │       ├─▶ 若当前未打开：从活动目录树移除索引（清理无效挂载）
                   │       └─▶ 若当前已打开：标记文档进入「外部已移除」告警态，禁止静默丢失，提示用户“重新保存至原路径”或“另存至草稿箱”
                   │
                   └── [事件类型：外部修改正文内容]
                           │
                           ├─▶ 当前未打开该文档：更新字数缓存与检索索引（若在全书检索或左栏只读对照视图展示，刷新视图）
                           │
                           └─▶ 当前已打开该文档（主栏或双栏任一侧）
                                   │
                                   ├── 本地状态为 Clean（无未保存修改）
                                   │       └─▶ 安全读取外部文件新内容 → 刷新编辑器画布（尽量保持当前滚动位置）→ 更新哈希与字数基准 → 轻提示“已同步外部更改”
                                   │
                                   └── 本地状态为 Dirty 或 Saving 失败
                                           └─▶ 【触发冲突防护】
                                               1. 立即冻结该文档自动保存队列，绝不覆盖磁盘；
                                               2. 弹出模态【版本冲突对比弹窗】，左右对比「本地版本」与「外部文件版本」差异；
                                               3. 等待用户显式三选一决策：
                                                  • [保留本地版本]：将本地内容强制原子覆盖磁盘，更新哈希基准，解除冻结并置为 Clean；
                                                  • [采用外部版本]：先为本地未保存修改留存一条保护快照（防后悔），再用外部内容覆盖编辑器，解除冻结并置为 Clean；
                                                  • [将冲突内容另存至草稿箱]：将本地未保存修改（冲突版本）另存为草稿箱中带时间戳的新草稿（`原名_冲突副本_时间.txt`），同时主编辑器采用外部最新版本刷新并解除冻结，确保两份内容均 100% 安全留存。
```

### 4.6 章节历史快照与版本对比回退流程（FR-3.6）

1. **手动快照流程**：
   - 用户在「历史快照」抽屉点击「新建快照」，填写可选备注（缺省默认“手动保存的版本”）；
   - 将当前编辑器最新正文、有效字数、创建时间与备注写入 `_meta/snapshots/<docId>/`，立即更新抽屉列表（按日期分组倒序展示）。
2. **自动快照触发流程**：
   - **触发时机**：切换离开当前文档、关闭应用前安全收口、或单章持续编辑达到长周期检查点时；
   - **触发条件**：对比当前正文与“最近一次快照正文”的有效字数净变动量（`Math.abs(currentWords - lastSnapshotWords)`）或字符差异量是否达到阈值（默认 `>= 300` 字）；
   - **按日滚动策略**：若今日尚无自动快照且变动达阈值，新建当日自动快照；若今日已有自动快照且后续继续产生达阈值变动，可按规则更新当日滚动快照或保留固定节律（兼顾磁盘空间与颗粒度），并与手动快照明确区分标识。
3. **版本对比与回退流程**：
   - 用户点击任意历史快照 → 后端读取对应快照文本，与当前编辑器正文执行行级/词级 Diff 计算，弹窗左右并排展示差异高亮；
   - 用户点击「恢复此版本」并确认 → **系统强制先为当前编辑器正文创建一条手动/保护类型快照（备注如“回退前自动保护”）** → 用所选历史快照文本覆盖编辑器正文 → 更新字数并触发原子保存落盘 → Toast 提示“已恢复所选版本，当前正文已自动留存”。
4. **快照来源标识**：除手动与自动快照外，云端/外部冲突仲裁产生的备份快照单独打标（如 `云端冲突备份`、`本地冲突备份`），在时间线上以不同标记区分，便于用户识别“这是我主动保存的”还是“系统为防丢而留存的历史版本”。

### 4.7 单章查找与替换 & 全书关键词检索流程（FR-4.6, FR-4.7）

#### 单章查找与替换（`Ctrl/Cmd + F` / `Ctrl/Cmd + H`）
1. **唤起与记录**：记录编辑器当前选区；若当前已有选中文本，自动预填至查找输入框并立即执行查找。
2. **无痕高亮与导航**：
   - 按关键词（及可选“区分大小写”状态）遍历正文段落文本节点（跳过场景分割线 `---` 节点），通过**视觉装饰层**渲染命中高亮标记与当前聚焦高亮标记；
   - 展示 `当前命中序号 / 匹配总数`，支持 `Enter` / 按钮跳转下一项、`Shift + Enter` / 按钮跳转上一项，自动滚动使当前命中项处于视口舒适位置。
3. **替换逻辑与撤销保障**：
   - **替换当前**：仅替换当前聚焦的命中项，更新正文并重算剩余匹配项与序号，自动跳转至下一命中项；
   - **全部替换**：收集全部合法命中区间，在底层文本模型中作为**单次原子事务**统一替换为目标文本并写入编辑器撤销栈（支持按一次 `Ctrl/Cmd + Z` 整批撤销回退），绝不破坏或误删场景分割线 `---`。
4. **关闭清理**：点击关闭或按 `Esc` 收起查找浮层时，立即卸载查找高亮装饰层，保持正文未受结构破坏且不因纯查找产生无效 `Dirty` 状态。

#### 全书关键词检索（`Ctrl/Cmd + Shift + F`）
1. **检索数据源合并**：
   - 遍历当前作品下所有活动文档（**含「灵感与草稿箱」与所有卷下章节，严格剔除「回收站」内容**）；
   - 若某文档当前正在单栏或双栏编辑器中打开且存在未落盘修改，优先检索其**内存中的实时最新文本**，其余文档读取磁盘文件（带内存索引/缓存以保证长篇大书的检索速度）。
2. **结果呈现**：
   - 匹配文档标题与正文内容，列表展示命中文档名、所属位置（草稿箱 / 卷名）、最后编辑时间及命中位置前后上下文摘要（关键词高亮）。
3. **跳转定位**：
   - 用户点击结果（或键盘 `↑` / `↓` 选中后按 `Enter`）→ 关闭全书检索浮层 → 执行安全切章（保存原章 → 打开目标章）→ 自动滚动编辑器至该次命中的首次出现段落/偏移并施加短暂定位高亮提示。

### 5.1 全局主题与正文排版引擎联动流程（FR-5.1 ~ FR-5.3）

1. **排版参数管理**：
   - 在「正文排版」侧边抽屉内调节：正文字体（预设文学字体及系统已安装字体枚举）、字号（`14px–24px`）、行高（`1.6–2.2`）、段落间距、正文版心最大宽度、段首自动缩进两字符开关（默认开启）、对话文本高亮开关、打字机居中滚动开关。

2. **全局主题切换**：
   - 书架页右上角与工作台顶栏保持统一的「主题」入口，支持一键切换「纯白」「羊皮纸」「淡绿」「暗夜」四套护眼主题；

### 5.2 左右双栏对照视图协同流程（FR-5.4）

```text
[用户点击分屏按钮 / 按 Ctrl+\]
         │
         ▼
检测当前窗口可用宽度是否满足双栏最小宽度要求？
    ├── 否 ──▶ 提示“当前窗口较窄，建议先折叠左侧目录或拓宽窗口后再开启双栏”，中止或自动先折叠左侧目录后进入
    └── 是 ──▶ 激活双栏布局：
               • 右栏（主写区）：保留进入前正在编辑的文档及滚动位置
               • 左栏（对照区）：默认载入上次对照文档 / 分章大纲 / 上一章
               • 启用中间分隔线拖拽（指针拖拽 + 键盘方向键微调）并记忆宽度比例
```

**核心协同规则**：
1. **双栏独立编辑与对照**：左右两栏各自具备独立的文档选择器与滚动条，支持在同一部作品内任意两篇文档之间对照查看或同步修改。
2. **同文档双栏状态一致性（重点机制）**：
   - 当左栏与右栏选择了**同一篇文档 ID** 时，两栏展示同步提示（如“正在对照同一篇文档”），底层指向**同一份内存文档状态源（唯一 `title` + `paragraphs` 模型与单一保存队列）**，绝不各自维护独立副本；
   - 两栏仍保持**各自独立的视图状态（独立的光标选区 Selection 与独立的滚动位置 ScrollTop）**；
   - 在任意一栏修改标题或输入正文时，另一栏实时增量同步视图内容，同时自动按需修正另一栏光标偏移，且不干扰另一栏的当前滚动阅读位置；保存状态机统一对唯一文档实例触发一次原子写盘，彻底杜绝同文档双开自相覆盖的冲突。

### 5.3 专注模式与打字机居中滚动流程（FR-5.5）

1. **进入专注模式（按钮 / `F11`）**：
   - **保存布局快照**：记录进入专注前的左侧目录折叠状态（`wasSidebarCollapsed`）及当前分屏态；
   - **视觉收起**：隐藏顶部全局快捷栏、左侧目录树、底部状态栏以及非必要的浮层，保留纯净居中的正文（及标题）画布与右上角极简「退出专注」提示；鼠标移至编辑区顶部热区时可临时淡入章节栏操作按钮。
2. **打字机居中滚动联动**：
   - 仅当排版抽屉中「打字机居中滚动」开关开启时生效（重点服务于专注模式及沉浸写作状态）；
   - 在用户输入或键盘移动光标时（避开输入法 IME 组字合成期 `compositionstart` ~ `compositionend` 期间剧烈跳动），计算当前光标所在行纵坐标与视口垂直舒适焦点区（如视口高度 45% 处）的偏移差值，超过舒适容差时平滑滚动视口使输入行居中。
3. **退出专注模式（按钮 / `F11` / `Esc`）**：
   - 精确还原进入专注前记录的目录展开态与分屏布局态，并保持当前编辑文档与光标位置不断开。

### 5.4 底部状态栏与云备份同步交互流程（FR-3.5 配套）

#### 5.4.1 保存状态区

实时反馈当前主编辑文档（或双栏最近活动文档）的保存状态机结果（`已保存` / `保存中…` / `保存异常`）。异常状态下允许点击查看详细原因并触发立即重试。注意区分两类状态：**保存状态**描述“本地磁盘是否写好”，**同步状态**描述“云端是否备份成功”，两者互相独立，不得混用同一枚指示器。

#### 5.4.2 云备份状态指示（状态栏云朵）

- **视觉**：极简「云图标 + 状态圆点」，不显示常驻文字；绿色圆点表示已关联云目录且同步正常，暖橙色圆点表示未连接/存在待推送/存在冲突或同步异常（避免刺眼红色）。
- **悬停**：展示一行主状态说明；异常或未连接时下方以小字补充具体原因（如“尚未关联云备份目录”“云目录当前不可写入”“检测到 2 处版本冲突”）。
- **点击**：唤起**极简「云备份与同步」浮层**（见 5.4.3），继续保持无用户账号头像、无社交资料的克制风格。

#### 5.4.3 「云备份与同步」浮层内容

1. **关联状态**：当前绑定的云备份目录路径（可「更换」或「解除关联」）；未关联时展示「选择云盘同步文件夹」入口与一句话说明（云盘客户端已负责上云，本软件只做双向备份）。
2. **同步概览**：上次成功同步时间、待推送文件数、待拉取文件数、是否存在未处理冲突。
3. **操作**：`立即同步`（手动触发一次完整检查与增量推送）、`查看同步记录`（近期成功/失败事件列表，仅保留轻量最近若干条）。
4. **打开检测设置**：`打开书库时检查云端更新`（默认开启）、`仅云端有更新时自动拉取`（默认关闭，关闭时按 4.4.6 的确认制提示）。

#### 5.4.4 打开时的更新提示交互

- 仅云端更新且条目较少时：以轻量浮层/Toast 形式展示「检测到云端有 N 个文件更新，是否从云端更新？」并给出「更新」「稍后」两个操作，避免打断沉浸写作。
- 条目较多或涉及整部作品结构调整时：使用列表式确认浮层，逐项展示作品名与待更新章节数量，确认后统一拉取。

#### 5.4.5 冲突弹窗交互（联动 4.4.6）

模态对比界面保持与「历史快照对比」一致的左右并排布局：左侧本地版本、右侧云端版本，差异词句高亮；底部并排三个动作——`保留本地版本`、`采用云端版本`、`另存冲突副本`。**任一选择都会把未被采用的一方自动写入历史快照**，并在确认按钮旁以小字明示该行为，让用户在点击前就清楚“另一版不会丢”。

## 6. 精准字数统计、码字日历与平台交付流程

### 6.1 字数统计口径与性能保障流程（FR-6.1, NFR-1）

1. **统一统计口径**：
   - **本章有效字数** = 汉字 + 中英文标点符号 + 连续英文单词/数字字符；
   - **严格剔除项**：所有空格（全角/半角）、制表符、换行符、章节独立标题栏内容，以及**独占一行的场景分割线符号 `---`**（注：段落正文内部的破折号 `——` 或普通短横线 `-` 属于常规标点，照常计入）。
   - **纯汉字数** = 仅匹配 CJK 统一汉字区间字符（不含标点、数字与字母）。
2. **局部增量计算保障流畅度**：
   - 当面对单章万字以上长文高速输入时，编辑区按键事件只对发生变更的段落执行局部字数重算并维护段落字数缓存表，章节总字数直接求和缓存表（`O(1)` 级实时更新），防止全篇正则扫表导致输入掉帧。
3. **字数明细面板联动**：
   - 底部状态栏常驻显示当前聚焦文档的有效字数；
   - 点击或悬停字数区域弹出明细卡片，展示：`有效字数（汉字 + 标点等）`、`纯汉字数（不含标点）`、`本章今日净增字数`、`全书总字数`，并提供「查看码字日历」跳转入口。

### 6.2 每日码字统计日历（热力图）核算流程（FR-6.4）

```text
文档有效字数变化
    │
    ├── 属于【正常手工创作 / 删改 / 粘贴】
    │       └─▶ delta = newWords - doc.countedBaseline
    │           将该 delta 累加至当前本地自然日 (YYYY-MM-DD) 该作品的 netDelta
    │           同步更新 doc.countedBaseline = newWords
    │
    └── 属于【非手工码字批量事件】（外部导入 / 软删除移入回收站 / 从回收站恢复）
            └─▶ 直接更新或冻结 doc.countedBaseline = newWords（不向 daily_stats 写入 delta）
                避免导入旧稿件虚高全年色阶，或删章引起巨额负值
```

**日历核算与展示规则**：
1. **自然日切分与负值保护**：以设备本地时区 `00:00:00 – 23:59:59` 为单日统计周期。若用户在写作过程中跨越零点，自动切分出新的自然日条目记录后续增量；若因大幅删稿导致某日累计净增字数为负值，账本按真实差值记录但**日历界面及统计指标展示值统一以 `0` 计**。
2. **多维度切换与聚合**：
   - 支持切换统计范围：**「全部作品汇总（当前书库）」** 或 **「单部作品」**（可从书架首页直接查看全部，或从工作台字数面板打开查看当前作品/全部）；
   - 指标计算：年度热力图格子（365/366 天按日强度 5 档色阶展示）、连续创作天数（当日展示净增 `> 0` 计为有效创作日）、当月累计码字、当年累计码字；悬停或点击方格显示具体日期与当日净增字数。

### 6.3 发布格式预设、一键复制与单章导出流程（FR-6.2, FR-6.3）

1. **发布格式预设配置流**：
   - 顶栏「预设」入口独立管理以下 4 项全局配置（修改即自动持久化，同时控制「复制本章」与「平台格式导出」）：
     - `段首补齐两个全角空格 (　　)`（开关）；
     - `段落之间额外保留一行空行`（开关）；
     - `首行自动附带章节标题`（开关）；
     - `场景分割线输出样式`（单选：`———` / `***` / `空行`）。

2. **发布文本格式化转换流水线**：
   - **输入**：当前文档标题 + 纯净正文段落/分割线序列；
   - **处理流程**：
     1. 遍历每一个正文块：
        - 若为**普通段落**：剥离段首尾空白；若开启“段首补齐两个全角空格”，拼接 `　　` 前缀；
        - 若为**场景分割线**：按预设替换为 `———`、`***` 或空行占位符；
     2. 确定段落连接符：若开启“段落之间保留一行空行”，连接符为 `\n\n`；否则为 `\n`（当分割线输出样式选为「空行」时，智能处理分隔前后换行，确保仅呈献清晰的空行过渡而不产生多余连续空行）；
     3. 若开启“首行附带章节标题”，将章节标题置于最前并以相同连接符接续正文第一段。

3. **一键复制与单章导出动作**：
   - **复制本章**：执行上述格式化流水线 → 将结果写入系统剪贴板 → 计算输出文本的有效字数 → 弹出 Toast 提示：“已按发布格式复制，共 X,XXX 字”。
   - **导出本章**：弹出双模式选择弹窗：
     - **模式 1：纯净原稿格式（`.txt`）**：保留原始极简段落换行与 `---` 分割线语义，可选是否首行附带章节标题；
     - **模式 2：平台发布格式（`.txt`）**：严格沿用全局发布格式预设转换；
     - 调用系统原生保存文件对话框由用户选定本地目标路径（默认建议文件名如 `<章节名>.txt` 或 `<章节名>-发布版.txt`）→ 将 UTF-8 副本写入目标路径 → 弹出轻量成功提示并明确强调**书库中的原始文件未作任何改动**。

## 7. 全局快捷键、窗口适配与异常处理矩阵

### 7.1 桌面端快捷键路由与优先级（NFR-3）

> **作用域优先级（由高到低）**：`确认/冲突模态弹窗` > `抽屉/浮层/查找框` > `专注模式` > `编辑器与工作台全局`。高优先级激活时拦截冲突按键（如 `Esc` 逐层关闭浮层或退出专注）。

| 功能动作 | Windows 快捷键 | macOS 快捷键 | 生效作用域与说明 |
| :--- | :--- | :--- | :--- |
| 立即触发保存 | `Ctrl + S` | `Cmd + S` | 工作台全局（触发立即落盘并更新状态反馈） |
| 撤销 / 重做 | `Ctrl + Z` / `Ctrl + Y` | `Cmd + Z` / `Cmd + Shift + Z` | 标题框与正文编辑器独立撤销栈（批量替换一步撤销） |
| 本章查找 | `Ctrl + F` | `Cmd + F` | 工作台开启或聚焦查找浮层（有选区时自动填入） |
| 本章查找并替换 | `Ctrl + H` | `Cmd + Option + F` / `Cmd + H` | 工作台开启查找替换浮层并聚焦替换输入框 |
| 全书检索 | `Ctrl + Shift + F` | `Cmd + Shift + F` | 工作台全局开启全书检索浮层 |
| 左右双栏分屏开关 | `Ctrl + \` | `Cmd + \` | 工作台全局切换单栏/双栏对照视图 |
| 专注模式开关 | `F11` | `Ctrl + Cmd + F` / `F11` | 工作台进入或退出专注模式（支持 `Esc` 退出） |
| 关闭当前浮层 / 退出专注 | `Esc` | `Esc` | 按优先级逐层收起弹窗、抽屉、查找框或退出专注模式 |

### 7.2 窗口尺寸适配与焦点恢复规则（UI设计 7）

1. **窄窗口自适应规则**：
   - 常规桌面宽度：展示完整左侧目录树 + 中央写作区；
   - 窗口收窄时：优先适度压缩侧边目录宽度；触及更窄断点时，左侧目录自动折叠为边缘可唤出抽屉，保证正文写作区获得充足空间；
   - **双栏宽度保护**：当窗口宽度低于双栏最小可用宽度时，禁止无限制压缩两栏导致文字折行混乱，自动提示用户关闭左侧目录或退出分屏。
2. **键盘焦点流转**：
   - 弹窗、抽屉与浮层打开时自动把焦点引导至首个有效输入框或操作项，内部限制 `Tab` 焦点循环；
   - 浮层关闭后，自动将焦点安全归还至唤起前所在的编辑器或触发按钮，保持连续键盘创作流不中断。

### 7.3 关键异常与安全边界矩阵（NFR-2）

| 异常/边界场景 | 检测时机 | 系统处理动作 | 用户交互反馈 |
| :--- | :--- | :--- | :--- |
| **本地文件被外部程序锁定/无权限写入** | 原子写入或文件重命名时 | 保留内存未保存文本与 Dirty 状态，绝不写空或破坏原文件；重命名失败则回滚名称 | 状态栏持续展示红色/警示态「保存异常」，提供具体错误说明与手动重试/另存出口 |
| **云盘同步造成本地与外部同时改动** | File Watcher 检测到外部变更且本地处于 Dirty 态 | **立即锁定自动保存**，严禁覆盖任何一方内容 | 弹出模态【版本冲突对比弹窗】，提供三选一决策直到完成解除锁定 |
| **双端离线各自修改同一章节（打开时发现）** | 打开书库/作品时三向比对判定 `Local ≠ Base` 且 `Cloud ≠ Base` | 冻结该文件两侧写入；不做静默覆盖 | 弹出模态版本对比，选择保留一方后**自动将另一方存为历史快照** |
| **云端文件缺失而本地存在** | 同步检查发现 `Cloud` 侧条目消失 | 默认不删除本地文件，等待用户裁决 | 提示「重新备份到云端」或「按云端删除移入本地回收站」 |
| **本地文件缺失而云端存在** | 同步检查发现 `Local` 侧条目消失 | 默认向云端恢复，避免误删导致丢失 | 提示「从云端恢复」或「确认删除云端副本」 |
| **云备份目录不可访问/被网盘占用** | 推送或拉取时探测目录失败 | 保留 `PendingSet` 待推送队列，不阻塞本地写作；稍后自动重试 | 云朵转为暖橙色，悬停说明“本地修改尚未备份，云目录当前不可写入” |
| **当前打开文件被外部重命名或删除** | File Watcher 捕获重命名/移除事件 | 重命名则自动追踪更新索引；删除则将内存文本转入“外部缺失保护态” | 重命名轻提示更新；删除则提示“磁盘原文件已移除”，引导立即重存回原处或转存草稿箱 |
| **误删除章节/整卷/作品** | 点击删除操作时 | 章节/卷执行软删除移入 `_trash/` 保留 180 天；彻底删除及删作品拦截确认 | 软删除后轻量提示可从回收站恢复；彻底删除/删作品强弹窗说明影响路径及不可逆性 |
| **恢复章节时原所属卷已删除** | 在回收站点击恢复单章 | 校验 `originalParentId` 状态发现原卷不存在或也在回收站 | 提示并引导选择：恢复至其他现有卷 / 移入草稿箱 / 连同原卷一起恢复 |
| **异常断电或进程崩溃后重启** | 应用写入保护机制 & 启动检查 | 原子写入（`.tmp` + `rename`）保证原磁盘文件要么为旧完整版要么为新完整版，不留残缺半成品 | 若存在未清理的 `.tmp` 孤立临时文件，启动检查时不破坏正式 `.txt` 原稿并安全清理或供校验 |
| **导入目录含不支持的非 `.txt` 文件** | 导入扫描预览阶段 | 过滤并忽略 `.docx`/`.pdf` 等格式，仅解析 `.txt`；源文件全程只读 | 在导入预览列表下方清晰提示跳过的非 `.txt` 文件数量，并声明“绝不改动原始文件” |
